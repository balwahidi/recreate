# Audit of the October 2026 GPT-6.1 Sol experiments

Source: [`handoff/`](../../handoff/) (first published on branch `codex/claude-handoff-2026-10-07`), `handoff/HANDOFF.md` and `handoff/recreate-claude-handoff.tar.gz` (SHA-256 `f6655b4f…a424`, verified). All 1,105 payload files match `MANIFEST.json`, and none is unlisted. The archive holds upstream fixes and outcomes, so it must not reach evaluated agents.

The two experiments are Experiment 1 (pnpm-16217, skill off vs on, 3 pairs) and Experiment 2 (current skill vs a one-rule simulation candidate, 3 pnpm-16217 pairs and 3 eslint-19924 pairs). Both ran GPT-6.1 Sol at medium effort.

The handoff's conclusions hold:
- Exp 1 shows a discipline benefit: no speculative production edit and no POSIX regression.
- Neither arm produced a fix-sensitive pnpm reproduction.
- The Exp 2 candidate failed its frozen gate.

## Findings the handoff understates or misses

1. **The tested "current" skill is an unmeasured edit of the shipped one.** Both experiments ran the 291-word working copy, never the 289-word v3 in `SKILL.md`. The working copy rewrites two rules. One is the flaky-rate rule, which has the strongest single-rule evidence in `docs/results.md` (rate stated 3/3 with the rule, 1/2 minimal, 0/3 control). No run compares 291 with v3, so GPT-6.1 Sol results describe the working copy only. The copy is preserved byte for byte as `evals/variants/SKILL-working-291.md`. The root `SKILL.md` is unchanged.
2. **Exit status is a gap in the skill, across both models.** `SKILL.md` asks for "**Run** (one command)" and never says what its exit status means:
   - GPT-6.1 Sol: 3 of 5 completed eslint-19924 artifacts reached the real symptom but exit 0 while the bug is present.
   - Devin: all 3 ripgrep-3009 reproduce artifacts, in both arms, end in `; echo`, so they exit 0 on both sides and the hang shows only in logs. ts-60573 control r2 graded on `tsc`, whose non-zero exit is by design.

   These artifacts are fix-sensitive or faithful, but none is usable as a regression check. This is the failure Experiment 3 targets.
3. **The grader mislabelled inverted harnesses.** A 0 → 1 replay was called `fails_both` even though the pre side passed. `classify()` in `evals/grade.py` now returns `pass_to_fail` for it. All 99 stored verdicts here are unchanged. Only the three Exp 2 ESLint artifacts relabel.
4. **The fixing PR number was visible to every evaluated agent.** The Exp 1 directory, `recreate-pnpm-16221-20261007`, appears in every prompt of both experiments. Exp 2 agents were also pointed at a dependency cache inside that tree, which also contains `controller/upstream-production.patch`. Of 400 recorded command events, none touched `controller/`, another run, or a PR URL, and no final message mentions 16221. Telemetry only covers recorded commands, though. The leak risk is low, but future runs need neutral directory names and evidence outside the agents' filesystem.
5. **Exp 1 timing is confounded.** The 79.5-second setup pause hit 2 of 3 skill-on runs and 1 of 3 skill-off runs. The report excludes the pause itself, not any knock-on delay. Treat "29% slower" as inconclusive.
6. **Exp 2 order was not counterbalanced.** All three ESLint pairs ran the candidate first (disclosed). Exp 3 forces both orders within every case.

## What the evidence supports

- For GPT-6.1 Sol on pnpm-16217, the skill prevents speculative production edits and the regressions they caused (3/3 pairs).
- Neither arm, nor the simulation candidate, gives a reproduction that passes after the real Windows-only fix. Labelling a simulation does not make it sensitive to the fix.
- On eslint-19924, faithful evidence is common (5/5 completed artifacts). Exit polarity, not fidelity, decides the primary grade.

The skill's discipline effect replicates on a second model. Its effect on the primary metric (a reproduction that fails before the real fix and passes after) is unproven on GPT-6.1 Sol. The cheapest measurable lever is the Run contract (Experiment 3, `exp3-run-contract.md`).
